Robot Manipulation · Temporal Representation Pretraining

Action-Effect Memory

A compact memory pretraining framework that compresses long-horizon vision-action interaction history into a single temporal representation for downstream robot policies.

AEM Mamba Encoder Masked Autoencoding One-Token Memory
Opening: Today I will present Action-Effect Memory, or AEM. The key idea is to pretrain a compact temporal memory for robot manipulation, instead of relying only on the current visual frame.
Background

Single-frame visual encoding is not enough

Manipulation is temporal

  • Robots often face occlusions, contact changes, and delayed environment responses.
  • The current observation may not reveal the true task state.
  • Similar images can correspond to different manipulation stages.
Background: Most prior representation pretraining methods focus on single-frame visual encoding. However, manipulation is a sequential interaction process, so the current frame alone is often insufficient.
Problem

Stacking history is costly and unstructured

Direct history stacking

  • Input size grows with the history horizon.
  • Computation, memory usage, and latency all increase.
  • Temporal abstraction is left entirely to the downstream policy.

What AEM aims to learn

  • A memory built from vision-action interaction history.
  • A dense and compact representation with fixed size.
  • A temporal structure that captures action-state dependencies.

Motivation: The key question is not whether history is useful, but what form of memory robot manipulation actually needs. AEM learns a compact, action-conditioned memory during pretraining.
Core Idea

Encode how actions change the world

1

Vision + Action

The memory is learned from interaction history, not visual observations alone.

2

Compact

AEM compresses the entire history into a fixed-size temporal state.

3

Action-Effect

Masked reconstruction encourages the memory to model action-conditioned state evolution.

In short, AEM pretrains a reusable memory that summarizes what happened and how the robot's actions affected the scene.

Core idea: AEM is not just compressing visual history. It explicitly includes actions, because in manipulation the world changes because the robot acts on it.
Method I

Final vision token as a temporal bottleneck

Single-vector memory

  • Visual and action features are projected into a shared token space.
  • They are interleaved in chronological order.
  • A Mamba encoder models the sequence context efficiently.
  • The encoded final vision token is reused as the compact history state.
Method: We interleave visual and action features and feed them into Mamba. Instead of adding a dedicated memory token, AEM uses the encoded final vision token as the compact history representation.
Method II

Masked action-effect pretraining

Training objective

  • Mask visual and action tokens together at selected time steps.
  • Keep the final visual token visible as the compression anchor.
  • Decode masked vision-action pairs using only the compact memory as global context.
  • Optimize visual and action reconstruction with MSE plus cosine distance.
Training: AEM applies aligned masking at the time-step level. By reconstructing missing visual and action content from incomplete histories, the final token is encouraged to capture temporal dependencies and action effects.
Policy Integration

A lightweight plug-in for downstream policies

Standard visuomotor policy

at = π(vt, pt)

The policy mainly relies on the current visual feature and task condition.

AEM-enhanced policy

The policy receives temporal context through one pretrained memory vector.

Diffusion Policy ManiFlow / Flow Policy No growing history tokens
Integration: After pretraining, the AEM encoder is used to extract memory from the history window. This memory is concatenated with the current feature and passed to the same policy backbone.

Ablation Study

What makes AEM work?

Fusion

Concatenating memory with current visual features works better than simple feature addition.

Pretraining signal

Reconstructing both observations and actions outperforms observation-only pretraining.

Feature choice

DINOv2 CLS features provide the strongest compact memory in the reported ablation.

Practical settings

  • A 32-step pretraining window and a 16-step inference history work best in the reported setup.
  • A 70% aligned time-step mask ratio gives the strongest downstream performance.
  • AEM should complement current perception, not replace it.
Ablation: The results show that AEM benefits from action-aware pretraining, a sufficiently hard masking ratio, and using the memory jointly with the current observation.
Conclusion

Pretrain memory, not just perception

Main contributions

  • A temporal representation pretraining paradigm for robot manipulation.
  • A compact final-token memory built from interleaved vision-action history.
  • A masked action-effect reconstruction objective for learning temporal dependencies.
  • Consistent improvements in simulation, randomized scenes, memory-dependent tasks, and real robots.

AEM shows that history does not have to enter a policy as more frames. It can be pretrained into a compact, transferable, action-aware memory.Thank you!

Closing: AEM compresses long-horizon vision-action history into one memory vector and injects it into existing policies. This gives the policy temporal context with low interface cost.
